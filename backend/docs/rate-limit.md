# 请求限流

后端复用启动时建立的 Redis 连接，通过 Lua 原子检查计数、递增和设置首次过期时间。窗口从首次请求开始，后续请求不刷新 TTL；超限请求不递增也不续期。固定窗口在交界处允许短时突发。

## 规则

限流阈值和窗口统一维护在 `internal/middleware/rate_limit_rules.go`，按操作和维度直接查找，不从 YAML 读取。业务端、操作和维度使用该文件定义的常量。调整规则后需要重新构建并重启后端。App 和管理端使用同一组阈值、不同的 Key。已登录账号共享普通额度，密码修改、请假提交、反馈提交和头像上传额外消耗各自专项额度。登录、注册使用独立额度，不消耗普通额度。

| 操作 | IP 额度 | 账号额度 |
| --- | --- | --- |
| 普通接口 | 600 次/60 秒 | 60 次/60 秒 |
| 登录 | 60 次/60 秒 | 10 次/60 秒 |
| 注册 | 20 次/60 秒 | 3 次/600 秒 |
| 修改密码 | 叠加普通额度 | 5 次/600 秒 |
| 提交请假 | 叠加普通额度 | 5 次/60 秒 |
| 提交反馈 | 叠加普通额度 | 3 次/600 秒 |
| 上传头像 | 叠加普通额度 | 3 次/60 秒 |

普通账号额度为页面初次加载、切换和筛选保留突发余量；请假和头像操作频率较低，使用更小的专项额度。共享出口及当前反向代理行为下不下调 IP 额度。上述阈值基于现有代码请求链路，仍需结合实际流量观察误限情况。

Key 为 `leave:<业务端>:<操作>:<维度>:<明文标识>`。业务端为 `app`、`admin`；操作为 `general`、`login`、`register`、`password-change`、`record-create`、`feedback-create`、`avatar-upload`；维度为 `ip`、`account`。标识直接使用明文账号或 IP，IP 先规范化（IPv4 映射地址转回 IPv4），账号去首尾空格；账号按输入区分大小写计数，admin 和 Admin 使用独立额度；数据库账号及关联字段需先应用 000012 迁移。例如 `leave:app:login:account:202410201016`、`leave:app:login:ip:127.0.0.1`。旧摘要 key 等待原 TTL 自动过期，新格式从零计数，无需清库。

IP 和账号依次独立计数，任何一层拒绝即终止请求，先前消耗的额度不回退。登录注册先消耗 IP 额度，通过参数校验后消耗账号额度，成功失败均不清空计数。登录后的账号取自认证上下文，不依赖客户端另传的学号或 Token 字符串。

后端仅信任同机代理（127.0.0.1、::1）的 `X-Real-IP`，Nginx 必须用 `proxy_set_header X-Real-IP $remote_addr` 覆盖该头。经过 Nginx 时按客户端 IP 限流；公网直连后端时忽略转发头，使用连接来源地址。`X-Forwarded-For` 不参与 IP 识别。若将来增加 CDN 或其他代理，需重新核对代理链路及可信地址，不能直接信任客户端传入的 IP。

健康检查、版本查询、安装包下载、OPTIONS 不参与本次限流。未知路由仍沿用原有行为。

## 响应与故障

超限返回 HTTP 429、业务码 2008、`message` 和 `data.retry_after`（向上取整，至少一秒），同时设置 `Retry-After`，CORS 允许读取该头。客户端沿用原有错误提示，不清除登录态，不自动重试。

单次 Redis 检查最长 500 毫秒，继承请求上下文；共享 Redis 客户端关闭命令自动重试，避免丢失响应后重复扣减。Redis 错误或异常计数状态返回 HTTP 503、业务码 9002，日志记录操作及维度，不主动记录标识、完整 Key、密码或 Token。

## 验证

在 backend 目录执行 `go test ./...`、`go build ./...`。真实 Redis 测试需显式提供 `RATE_LIMIT_TEST_REDIS_ADDR=127.0.0.1:<独立测试端口>`，仅接受 loopback 地址。测试只操作随机测试标识生成的 Key 并清理，不执行 FLUSHDB，不使用开发隧道或生产 Redis。未设置时跳过真实 Lua、并发及 TTL 集成测试，不算通过。

限流器是必需依赖，不允许通过 nil 绕过检查。路由及 Handler 测试也需提供独立本机 Redis（RATE_LIMIT_TEST_REDIS_ADDR）；未配置时相关测试跳过，不能视为通过。Redis 启动连接失败则启动失败，运行中操作异常则返回限流服务异常，不放行。

客户端账号维度统一为 account；升级后旧 student 维度的计数不再使用，等待原 TTL 自动过期，账号额度从新 key 开始计数。
