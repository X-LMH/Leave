# 客户端开发规范

本文件适用于 `frontend/`，与根目录 `AGENTS.md` 的共同约定一起遵循。未带模块前缀的路径相对于 `frontend/`；带 `frontend/` 等前缀的路径相对于项目根目录。

## 目录职责与平台边界

* 客户端使用 uni-app x、UTS 和 uvue，主要运行在 Android；不要直接套用 Web Vue 的 API、DOM 操作或样式方案。
* `pages/` 保存业务页面，`components/` 保存复用组件，`utils/` 保存公共逻辑，`static/` 保存静态资源；优先复用已有实现。
* 新增或调整页面时检查 `pages.json` 的注册和导航配置；应用版本、图标及打包配置以 `manifest.json` 为准。
* 接口封装位于 `utils/api.uts`，请求地址、Token、响应类型及公共请求处理沿用该文件约定，不在页面中重复实现。
* 页面数据来源和联调阶段遵循根目录规范；已有真实请求保持现有链路，Mock 或占位功能仅在明确要求时接入接口。
* 权限、文件路径、头像选择、下载和安装流程优先按 Android 真机行为处理；其他平台按具体任务要求适配。

## 页面与交互

* 除非需求明确要求调整该页面，保留 `pages/leave/detail.uvue` 当前呈现出来的样式。
* 接口联调和逻辑修改遵循根目录的代码修改边界，保留已有表单、交互和确认流程，不顺手重新设计 UI。

## uni-app x / uvue CSS 约束

* uvue 仅使用 class 选择器，不要使用 `page`、`body`、`html` 等标签选择器。
* 不要使用 `100vh`、`100vw` 等视口单位。
* `height`、`min-height` 等属性优先使用明确的 `px`、`rpx` 尺寸，或沿用现有 flex 布局；百分比高度需确认父容器尺寸并验证 Android 渲染，不仅为统一单位改写现有布局。
* 添加或修改样式前先检查已有定义，不要通过重复声明相同 class 来覆盖旧样式。

## 验证

* 当前客户端没有 `package.json` 或 npm/pnpm 构建脚本，使用 HBuilderX 的 uni-app x 编译和 Android 运行流程；不为套用 Web 验证命令新增包管理配置。
* 页面修改检查实际渲染、导航和相关交互；涉及权限、文件、下载或安装时优先在 Android 真机验证。
* USB 调试出现网络问题时，先检查现有请求地址、后端服务及 ADB 反向转发，参考项目已有连接脚本或调试技能，不直接修改生产请求地址。
* 无法使用 HBuilderX 或 Android 设备时，说明已完成的静态检查和未验证的运行行为，不声称编译、视觉或真机验证通过。
* `unpackage/`、`.hbuilderx/` 等本地产物遵循根目录 `.gitignore`，不混入源码提交。
